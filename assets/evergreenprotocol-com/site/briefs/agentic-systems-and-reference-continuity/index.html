Intelligence brief · Reference Decay Series · Brief 002

Agentic Systems and Reference Continuity

Enterprise agentic systems do not only rely on models. They rely on institutional references — policies, approval rules, risk thresholds, vendor definitions, knowledge-base articles, and machine-readable governance files — that change over time. This brief examines five operational cases in which an agent executes correctly while the reference it acts on has decayed.

What enterprise agents rely on

An enterprise agent deployed for workflow automation, procurement routing, compliance checking, knowledge retrieval, or operational decision support does not operate from model capability alone. It operates against institutional references: the policies, rules, definitions, and documentation that govern what it is supposed to do.

Those references include:

  • Approval policies and authorization rules
  • Risk thresholds and tolerance limits
  • Vendor definitions and approved-supplier lists
  • Data-use policies and classification rules
  • Knowledge-base articles and procedural documentation
  • Workflow instructions and routing logic
  • Machine-readable governance files (JSON, YAML, structured metadata)
  • Regulatory and contractual references embedded in governance documents

When those references are stable, versioned, and current, the agent performs as intended. When they are not — when they have been updated without version continuity, diverged between sources, or allowed to remain accessible after they have been superseded — the agent may execute correctly while the reference it acts on is no longer true.

Three failure modes

Enterprise AI governance typically focuses on two categories of failure. Reference failure is the third, and it is the category this brief addresses.

Model failure
The model behaves incorrectly: it hallucinates, misclassifies, or produces an unreliable output. Model safety, red-teaming, and evaluation frameworks address this category.
Execution failure
The system acts incorrectly: the agent takes an unintended action, triggers the wrong process, or produces a harmful downstream effect. System safety, guardrails, and operational controls address this category.
Reference failure
The model and agent execute correctly, but against a reference that is no longer true. The policy cited was valid when indexed. The approval threshold was accurate when the workflow was built. The vendor definition was current when the agent was trained on it. All of those things changed. The agent did not fail — the reference did. Evergreen Protocol addresses this category.

Case 1: The stale approval rule

An enterprise procurement agent routes approval decisions based on a spending authorization policy. The policy states that purchases under $50,000 may be approved at department level; purchases above that threshold require executive sign-off. The agent indexes the policy at deployment.

Twelve months later, a change in internal controls policy lowers the threshold to $25,000 for a specific vendor category following a procurement audit. The policy document is updated. The agent’s reference layer is not.

The agent continues routing $35,000 purchases in the affected category for department-level approval. The model performs correctly: it reads the rule it has and applies it. The execution is correct: the routing logic runs as designed. The reference is wrong: the agent is operating against a governance threshold that no longer exists.

No error is surfaced. The audit trail shows approved transactions, each with a reference to the authorization policy. What the audit trail does not show is that the policy version the agent consulted had been superseded before the decisions were made.

Case 2: The contradictory vendor definition

A large enterprise maintains two reference sources for the term “approved vendor”: a procurement policy administered by the finance function, and a vendor risk register maintained by the security function. The two definitions diverged eighteen months ago following an internal restructuring, but no reconciliation was completed.

An agentic vendor routing system was built against the finance function’s definition. When a new engagement request arrives for a vendor that appears on the finance approved list but was removed from the security risk register following a posture review, the agent approves the routing.

The model performed correctly. The routing logic executed as designed. The reference the agent was built against authorized the decision. The reference the agent was not built against had reached a different conclusion — and both were live, citable, and governance-issued documents within the same organization.

Definition divergence at this level is a reference continuity problem. No individual reference decayed; the relationship between them did.

Case 3: The silent risk-threshold update

A financial services firm deploys an agent to assist with credit exposure monitoring. The agent evaluates transaction-level risk against tolerance thresholds specified in the credit risk policy document. At deployment, the maximum single-counterparty exposure tolerance is documented at 8% of portfolio exposure.

Following a market event, the risk committee approves a reduction to 5%. The decision is recorded in meeting minutes and reflected in the updated policy document. The agent’s reference layer — the version of the policy it consults during evaluation — is not updated.

The agent continues flagging at 8% while the current governance limit is 5%. Transactions between 5% and 8% pass review without alert. The agent’s outputs are technically correct given the reference it has. The risk function and the agent are now operating against different versions of the same governance document.

The gap is not detectable from the agent’s outputs alone. It is only visible by comparing the agent’s active reference against the current policy version — a comparison that requires version discipline to make possible.

Case 4: The machine-readable drift

An enterprise knowledge governance team maintains a structured governance file in JSON that an agentic system consumes directly to enforce classification rules. The same governance logic is also published as a human-readable internal policy page.

Over six months, the human-readable page is updated three times: once to add a classification category, once to revise a definition, and once to adjust an approval requirement. The JSON governance file is updated for the first revision but not the second or third. The team did not have a synchronized update protocol between the human-readable and machine-readable forms.

The agentic system continues consuming the JSON file and enforcing the rules it contains. For classifications governed by the second and third revisions, the agent is enforcing a prior governance state while the organization believes it is enforcing the current one.

Human review of the policy page would show current rules. Machine review of the JSON file would show different rules. The agent consumes the JSON file.

Case 5: The archived-but-still-cited reference

A knowledge management team retires a set of internal procedural guides following a governance restructuring. The guides are moved to an archive state: they remain accessible at their original URLs but are marked as superseded in the governance inventory. No redirect, expiry header, or removal is implemented at the URL level.

An enterprise agent configured to retrieve and cite internal knowledge-base content does not distinguish between current and archived status. It retrieves the superseded procedural guides in response to relevant queries, cites them as references, and bases its downstream recommendations on their content.

Staff who receive the agent’s outputs see cited references with recognizable document titles and valid URLs. Nothing in the output indicates that the guides were superseded eight months earlier. The agent’s citations are accurate. The references are no longer valid governance.

This case is structurally distinct from the others: the reference was not changed in place. It was replaced. The problem is that the replacement was not propagated to the systems that cite it.

Why agents make reference decay worse

Compared to a human consulting a document, an enterprise agent operating on stale references creates compounding governance risk across six dimensions:

  • Agents act repeatedly, not once. A human consulting a decayed reference makes one decision based on it. An agent may execute the same stale reference thousands of times across a workflow cycle before the decay is detected.
  • Agents combine multiple references. A single agent output may draw from policy documents, risk registers, knowledge-base articles, and machine-readable governance files simultaneously. Decay in any one reference propagates into every decision that incorporates it.
  • Agents automate downstream actions. Where a human decision relying on a stale reference produces one incorrect outcome, an agent decision may trigger automated approvals, routing decisions, compliance filings, or communication chains before any human reviews the basis for the decision.
  • Agents may cite stale context confidently. An agent’s output may include citations and justifications that appear well-grounded. The confidence expressed in the output does not distinguish between a valid current reference and a reference that was accurate when indexed but has since changed.
  • Stale references scale across workflows. If a reference that feeds multiple agent workflows decays, the decay propagates into every workflow that consumes it. The scope of exposure is a function of the reference’s reach across agents, not the error rate of any individual decision.
  • Audit trails record what happened but not whether the reference was valid. Post-event review may confirm that the agent followed its instructions and cited a real document. It may not establish whether the cited document version was current at the time of the decision, unless version discipline was maintained in the reference layer.

Evergreen Protocol reading

Model governance asks whether the model can be trusted. Reference continuity asks whether the references the agent acts on are still valid.

Evergreen Protocol reads the agentic reference continuity problem through seven governance dimensions:

  • Reference decay — the decay of validity, traceability, citation stability, or operational reliability in references an agent consults; the central problem this brief documents across five operational cases.
  • Version discipline — explicit version history for policies, risk thresholds, approval rules, and machine-readable governance files, enabling reconstruction of the exact reference state an agent acted on at decision time.
  • Citation stability — the stability of reference paths over time, so citations embedded in agent configurations or retrieval systems continue to resolve to the correct governed content rather than archived, superseded, or altered versions.
  • Evidence posture — the capacity to establish, after the fact, what reference an agent acted on, what version of that reference was current at decision time, and whether the reference was still valid when the decision was made.
  • Definition control — governed reconciliation of terms that may appear across multiple reference sources with divergent meanings, preventing agents from routing decisions based on the wrong definition context within the same organization.
  • Changelog integrity — a maintained audit trail showing what changed in each governed reference, when it changed, and what the prior state was, enabling reconstruction of governance state at any point in time and across the full history of agent decisions.
  • Machine-readable reference alignment — alignment between the human-readable and machine-readable forms of governance content, so agents consuming structured files are not enforcing a prior governance state while the human-readable page reflects current governance.

What this brief does not claim

  • This brief does not certify that any agent, system, or organization is compliant with reference continuity standards.
  • It does not approve or endorse specific models, agent platforms, or AI governance frameworks.
  • It does not create a compliance status, score, rating, or registry entry for any party.
  • It does not replace model governance, AI safety review, legal review, audit, or model-risk management.
  • It does not imply that model safety and reference continuity are the same governance problem — they are not.
  • It does not claim that Evergreen Protocol prevents reference decay or that any protocol prevents all forms of agentic risk.
  • It does not claim that reference continuity resolves all governance challenges in agentic systems.
