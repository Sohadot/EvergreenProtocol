Machine-Readable Reference

Evergreen Protocol publishes static, versioned JSON reference files to support AI agents, institutional systems, RAG pipelines, citation tools, and governance workflows. These files are stable, citable, and require no authentication or dynamic backend.

Version pinning

Files under /en/protocol/v1/ are immutable after publication. They will not be modified when the standard is updated. Future standard versions publish at new paths: /en/protocol/v1.1/, /en/protocol/v2/, and so on.

The live definitions index at /en/definitions.json reflects the current active version and is updated when the standard advances.

This versioning approach ensures that citations made today remain valid and resolvable in the future, which is a direct application of the reference continuity principle this standard governs.

How to cite these files

To cite the machine-readable standard in a governance document or AI system prompt:

Evergreen Protocol v1.0 (2026). Machine-readable standard reference.
https://evergreenprotocol.com/en/protocol/v1/standard.json

For definitions citation, include the term and the definitions index URL:

Evergreen Protocol v1.0 (2026). Definition: [term].
https://evergreenprotocol.com/en/definitions.json

For human-readable citation formats, see How to Cite.

What these files do not provide

  • No certification or compliance verdict — these files document the standard and its definitions; they do not certify that any organization complies with the standard.
  • No live API or dynamic endpoint — all files are static. No authentication, rate limits, or service agreement applies.
  • No MCP endpoint — a Model Context Protocol-compatible layer is future-gated and not present in this architecture.
  • No readiness score or assessment — no scoring, ranking, or assessment logic is embedded in or returned by these files.
  • No external recognition or endorsement — these files reflect the internal governance of the Evergreen Protocol standard only.
  • No registry — no organization is listed as registered, endorsed, or compliant in these files.

File format and schema

All files use JSON with Schema.org @context and @type annotations where appropriate (DefinedTermSet, CreativeWork). They are served as static .json files with no server-side rendering.

Consumers should treat these files as reference data, not as executable API contracts. The authoritative human-readable source for all terms and governance statements is the HTML pages on this site.
